# Новый shell пролога — production-spec

Статус: **implemented in R1; local verification passed, device QA pending**  
Дата: 20 июля 2026

## 1. Задача и границы

Новый shell должен превратить пролог `silent-ruins` в цельное ежедневное
путешествие: главный экран показывает героя и одно актуальное действие, выбор
маршрута вынесен в отдельный полноэкранный шаг, а прибытие, выбор, память,
мини-игра и награда проходят внутри одной сцены.

Целевая аудитория — игрок на iPhone, который открывает игру короткими сессиями
и должен за несколько секунд понять, что произошло и что делать дальше.

Успех первой production-итерации:

- на главном экране нет постоянного графа маршрута и служебной верхней панели;
- иерархия шагов меняется между развилкой, движением и прибытием;
- точка не запускает каскад модалок автоматически;
- обычный выбор, память, взлом и бой используют один полноэкранный контейнер;
- результат и награды появляются внутри той же сцены;
- существующие сохранения, ID, стоимость путей, награды и правила мини-игр не
  меняются.

Первая итерация действует только в `silent-ruins`. Остальные локации и
неутверждённые экраны продолжают использовать существующий интерфейс до R2/R3.

## 2. Неизменяемые инварианты

- `GameSave` и вложенные структуры не получают новых полей.
- ID всех локаций, узлов, story encounters и minigames остаются прежними.
- `grantNodeReward`, `resolveStoryEncounter`, `resolvePointEventChoice`,
  `resolveCarefulCrossing`, `resolveLockpicking` и `resolveConnectBattle` остаются
  единственными источниками игровых результатов.
- Стоимость переходов, step bank, частичный прогресс, XP, монеты, пороги,
  количество ходов и размеры полей не меняются.
- HealthKit, нотификации, лагерь, герой, карта мира и migration/normalization
  продолжают работать через существующие сервисы.
- Арт, герой, навигация и интерактивные элементы остаются отдельными слоями.
- Игра остаётся строго портретной.

## 3. Допущения первой итерации

- Закрытая незавершённая сцена сохраняет локальную фазу и ввод, пока приложение
  остаётся запущенным. Уже зафиксированные story/minigame-фазы восстанавливаются
  после перезапуска из существующего сейва. Новый persistent draft не создаётся,
  потому что save shape заморожен.
- Текущие runtime-арты используются как production-safe fallback. Mobile-safe
  GPT Image изображения остаются только референсами и не входят в bundle.
- `Показать на карте` открывает существующую функциональную локальную карту.
  Карта мира продолжает открываться отдельным существующим экраном.
- Неутверждённые лагерь, герой, хроника и настройки визуально не
  перепроектируются в этой итерации.

## 4. Информационная архитектура и flow

```text
Путь: развилка
  -> Выбор маршрута
  -> Путь: движение
  -> Путь: точка достигнута
  -> Единая сцена
       -> intro/choice
       -> action (если есть)
       -> resolution
  -> Путь: следующая развилка или движение
```

Дополнительные переходы:

- `Показать на карте` -> существующая локальная карта -> `Назад к пути`;
- `Закрыть` из активной сцены -> Путь с CTA `Продолжить событие`;
- `Мир`, `Лагерь`, `Герой` -> существующие production-экраны;
- вечерний CTA -> `Лагерь`, вторичное действие -> обычный Путь.

## 5. Модель состояния

### Journey

| Состояние | Условие | Приоритет | Главное действие |
|---|---|---|---|
| `fork` | нет `activeTargetId`, есть доступные цели, нет pending scene | свободный `stepBank` | `Выбрать путь` |
| `route-choice` | открыт chooser | стоимость и остаток для выбранной цели | `Выбрать этот путь` |
| `travelling` | есть `activeTargetId` | шаги до цели | `Посмотреть путь` |
| `arrival` | текущая точка содержит незавершённую фазу | событие и его название | `Открыть/Продолжить событие` |
| `complete` | локация завершена, активной сцены нет | открытая дорога дальше | `Открыть мир` |
| `evening` | после 20:00, приглашение сегодня не скрыто, нет arrival | костёр | `Вернуться в лагерь` |

`СЕГОДНЯ` всегда вторично. Ноль свободного запаса не становится главным числом
во время движения. У прибытия не показывается `0 шагов` или завершённый progress
bar.

### Encounter

```text
intro/choice -> action? -> resolution -> closed
       \------------------ close -> journey -> resume
```

Разрешённые последовательности пролога:

- `quiet-camp`, `whispering-grove`: choice -> resolution;
- `sunken-road`: action/crossing -> resolution;
- `broken-arch`, `spire-overlook`: intro -> resolution;
- `forgotten-cache`: intro -> action/lockpicking -> resolution;
- `ash-guard`: intro -> choice/story -> action/battle -> resolution;
- `silent-shrine`: intro -> choice/memory -> resolution.

`resolution` использует базовую награду узла и уже рассчитанный бонус. Отдельный
battle report после закрытия shell в прологе не создаётся.

## 6. Визуальное направление

Источники: утверждённые `JOURNEY_FLOW_GPT_IMAGE_V2.md` и
`ENCOUNTER_SHELL_GPT_IMAGE_V1.md`, включая проверенные 390×844 previews.

Переносимые правила:

- живая тёмная диорама на всю высоту экрана;
- холодный сине-серый мир, зелёное свечение героя и один сдержанный тёплый
  акцент для главного действия;
- serif для эмоциональных заголовков и чисел, humanist sans для служебного
  текста;
- контент вырастает из нижнего затемнения сцены, без отдельной стеклянной или
  орнаментальной карточки;
- text-only navigation на главном экране; навигация скрыта внутри encounter;
- поверхности матовые, рамки тонкие, тени глубокие, без emoji и декоративных
  рун; карточки направления могут использовать крупные смысловые силуэты
  объектов как навигационные ориентиры, а не как статусные badges.

Не копируются буквальные пиксельные размеры или растровый текст референсов.
Production использует кодовую типографику, safe-area и адаптивные ограничения.

## 7. Экранные спецификации

### Путь — развилка

- Верх: `СЕГОДНЯ`, затем `В ЗАПАСЕ` и крупный `stepBank`.
- Центр: мир и герой в ожидающей позе.
- Низ: `ТРОПА РАСХОДИТСЯ`, короткая фраза, один primary CTA и вторичное
  действие `Карта пути` для ориентации до выбора.
- Навигация: `Путь`, `Мир`, `Лагерь`, `Герой`.
- При одной доступной цели экран всё равно использует chooser, чтобы цена и
  необратимость вложения были видимы до подтверждения.

### Выбор маршрута

- Полноэкранный дочерний экран без глобальной навигации.
- Верх: `Назад`, текущий запас и заголовок.
- 1–3 destination rows с названием, стоимостью, описанием, смысловым силуэтом
  (костёр, тайник, арка, страж, святилище или шпиль) и выбранным состоянием
  через рамку, свет и `aria-pressed`.
- Низ: точный остаток после вложения, primary CTA и текстовая ссылка
  `Показать на карте`.

### Путь — движение

- Главное число: `cost - activeProgress`.
- Вторично: `activeProgress из cost` и шаги за сегодня.
- Герой визуально движется по одному выбранному пути.
- `Посмотреть путь` открывает функциональную локальную карту; движение не
  требует ручного CTA.

### Путь — прибытие

- Главное: название точки и присутствие события.
- Вторично: свободный запас и шаги за сегодня.
- CTA открывает или возобновляет unified shell.
- Навигация остаётся доступной, пока игрок сам не открыл сцену.

### Путь — вечер

- Это состояние главного экрана, не модалка.
- Показывает текущий route context, костёр и мягкое приглашение.
- Primary CTA открывает существующий лагерь и помечает приглашение показанным.
- `Остаться в пути` только закрывает приглашение на текущий день.

### Единая сцена

- `position: absolute/fixed`, занимает весь viewport `phoneFrame`.
- Верхняя зона: `Закрыть`, eyebrow и контекстный арт.
- Нижняя зона: title, body, текущий выбор/механика/результат.
- Нет глобальной нижней навигации.
- В каждый момент одна primary action или один равноправный набор choice rows.
- На `resolution` показываются эмоциональное последствие, `Базовая награда`,
  `Бонус` и `Продолжить путь`.

## 8. Компоненты и поведение

### Journey navigation

- Интерактивная высота не меньше 44 pt.
- Активный пункт обозначается типографикой и нижней линией, не только цветом.
- `Путь` на текущем экране не вызывает лишнюю навигацию.

### Destination row

- Вся строка кликабельна, `aria-pressed` отражает выбор.
- Заголовок, описание и цена не обрезаются на 320–430 px.
- Выбор обозначается рамкой, контрастом и текстом `Выбран` для screen reader.

### Choice row

- Все варианты равного визуального веса.
- У memory ни один ответ не выглядит правильным.
- Story choice фиксируется только при нажатии на конкретную строку.

### Lockpicking

- Ровно три кодовые pin lanes и одна success band.
- Существующие скорость, ширины и расчёт rating не меняются.
- `Закрыть` ставит визуальный цикл на паузу; возврат продолжает текущий pin.

### Battle

- Ровно 5×5 кодовых cells и 6 ходов для `ash-guard`.
- Enemy intent остаётся рядом с полем.
- Focus symbol различим контуром и подписью, не только цветом.
- Результат переключает shell на `resolution`, не открывает report overlay.

## 9. Responsive и accessibility

- Основной target: iPhone 390×844; поддерживаемая ширина: 320–430 px.
- Safe-area учитывается сверху и снизу через `env(safe-area-inset-*)`.
- Длинный контент encounter прокручивается внутри shell; CTA не уходит за
  нижнюю safe-area.
- Touch targets не меньше 44×44 pt.
- Основной текст и controls должны соответствовать WCAG AA.
- `:focus-visible` обязателен для buttons и choice rows.
- Dialog получает `aria-modal`, связанный title и описательное состояние.
- `prefers-reduced-motion` отключает decorative drift/rise и smooth movement.
- Успех, выбранность и enemy focus сообщаются формой/текстом, а не только
  цветом.

## 10. Инженерный handoff и критерии приёмки

Реализация:

- новый прологовый Journey условно включается только для `silent-ruins`;
- существующий `MapScreen` сохраняется как функциональная карта и fallback;
- новый EncounterShell использует текущие resolver callbacks;
- old modal queue не рендерится для прологовых point/story/lock/battle фаз;
- завершение боя в прологе не устанавливает отдельный `battleReport`;
- за пределами пролога текущие модалки и поведение остаются без изменений.

Проверки:

1. Новый пустой сейв видит развилку и тот же набор target IDs.
2. Выбор цели списывает/вкладывает тот же `stepBank` через `startMapRoute`.
3. Частичный route progress и остаток совпадают с текущей логикой.
4. Прибытие выдаёт базовую награду ровно один раз.
5. Каждый из семи посещаемых узлов пролога завершает нужную последовательность
   внутри одного shell.
6. Story, point-event, lockpicking и battle results записываются в прежние
   ключи и не дублируются.
7. Закрытие незавершённой сцены возвращает на arrival и позволяет возобновить
   локальный ввод.
8. Старый сейв, уже находящийся внутри пролога, открывает корректное следующее
   состояние без миграции.
9. За пределами `silent-ruins` интерфейс и игровые результаты не меняются.
10. На 390×844 нет горизонтального клиппинга; выбор, три pins и 25 battle cells
    полностью видимы или доступны через вертикальную прокрутку.
11. `npm test`, `npm run lint` и `npm run build` проходят.

Открытый asset-risk: отдельного runtime-арта Пепельного стража пока нет.
Первая итерация использует существующую угрозу/руины как fallback; создание
уникального арта остаётся отдельной визуальной задачей и не должно блокировать
проверку shell-архитектуры.

## 11. Реализация R1

- `src/components/PrologueShell.tsx` — Journey, route chooser и единый
  encounter-контейнер;
- `src/components/prologueShellState.ts` — восстановление следующей фазы из
  прежних полей `GameSave`;
- `src/components/PrologueShell.css` — портретный visual shell, safe areas,
  focus-visible и reduced-motion;
- `src/App.tsx` — условное включение только для `silent-ruins`; прежний UI
  остаётся fallback для остальных локаций;
- `tests/game.test.ts` — регрессия восстановления незавершённой сцены без
  добавления persistent state.

Локально проверены развилка, выбор и движение по маршруту, прибытие, обычный
выбор, careful crossing, закрытие/возобновление, результат и экран взлома в
390×844. Финальная приёмка lockpicking, battle, memory и старого сейва должна
быть повторена на реальном iPhone после `npx cap sync ios`.

Финальный локальный прогон 20 июля 2026: `npm test`, `npm run lint` и
`npm run build` — успешно.
